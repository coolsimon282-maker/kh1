## What made things match (session 2 additions)

- **Bitfields fix "sd sinks below sw" scheduling**: func_001CECE0/func_001D8AF0/func_001DD7F8 matched when the
  0x328 flags are a u64 bitfield in an overlay struct (`ScriptX`, set `x->unk_328_2 = 1`). A bitfield store gets
  the struct's alias set, so GCC keeps it before the s32 stack loads.
- **Stack message struct** for func_001C4640 (`ScriptMsg`): `u64 unk_00 : 8; u64 unk_01 : 24; s32 unk_04; ...`.
  `msg.unk_00 = N; msg.unk_01 = 0;` gives the `sb` + `ld/and 0xFFFFFFFF000000FF/sd` sequence. Messages with a
  vector at 0x10 use `f32 unk_10[4]` (0, 0, 0, 1.0f) (`ScriptMsgF`).
- **`+4 base` (addiu rX, a0, 4 with offsets 0x17C/0x180)** comes out automatically from
  `unk_174[unk_174[3] + 3]` and `+ 4` in the same expression, and from `stack[top] = f(stack[top])`.
- **0xB0-stride tables** (D_006298F4.., D_0062990C, D_00629984): declare each symbol as an array of a local
  0xB0-byte struct whose first field is the accessed type (s16 / f32).
- **D_003010F8 as 0x74-byte records**: `((Elem74*)D_003010F8)[i].unk_00[0x36]` gives `off + base`;
  `u8* p = (u8*)D_003010F8; p += i * 0x74; p[4]` gives `base + off` (func_001DBC40).
- **Function-pointer globals** (D_00377340..D_003773E8): `extern void (*D_X)(s32, ...); D_X(args);`.
- **Post-decrement through a pointer**: target `addiu a1,a0,0x180; lw; ...; lw arg; jal; sw top-1` came from
  `s32* t = &arg0->unk_174[3]; s32 v = arg0->unk_174[*t + 4]; (*t)--; f(v);` (func_001CFBC0).
- **Return-value layout**: `s32 ret = 4; if (...) { ...; ret = 0; } return ret;` vs early returns change which
  path falls through; flip the test (`== 0`) when the target's branch is inverted.
- **Fields at fixed offsets of D_003854E0 past its struct** (0x3128, 0x312C): an overlay struct cast
  `((XGiantMountainX*)&D_003854E0)->unk_3128` keeps the D_003854E0 base register; a `*(s32*)&unk_3094[0x94]`
  cast makes a separate pointer.
- **Pointer vs s32 stores**: `*(void**)&arg0->unk_00[4] = f()` lets GCC reorder the store against s32 loads of
  the stack (func_001D3138); `*(s32*)` doesn't.
- **Small count loops**: `for (i = 3; i >= 0; i--) n += *p++ < 20;` keeps the forward pointer walk; a plain
  `for (i = 0; i < 4; i++)` over `arr[i]` got reversed by GCC (func_001D7940).
- **Checking many functions at once**: when one function's size is wrong, every later function shifts, so jal
  targets and %lo(data) offsets differ in the diff. Only trust 0-diff results, or recheck after fixing sizes.

## What made things match (session 1)

- Script stack: `unk_174[3]` (0x180) is the stack top, `unk_174[top + 4]` (0x184 + top*4) is the top value.
  Push = `arg0->unk_174[3]++; arg0->unk_174[arg0->unk_174[3] + 4] = X;` (FM loads X after the increment,
  JP's versions load it first through a temp).
- `x ? 4 : 2` gives `li a0,2; li v0,4; movz v0,a0,x`. If the li order is swapped, swap the ternary
  (`f() ? 2 : 4` rather than `f() == 0 ? 4 : 2`).
- u64 flag bits (D_0038CD00, D_0038CD08, Script+0x328): `((s32)(*(u64*)D_0038CD00 >> N) & 1) ? 4 : 2`.
  The (s32) cast before `& 1` removes the extra dsll32/dsra32. For N < 32 GCC emits `dsll (32-N); dsra32 0`.
- Aliasing: a store to a plain scalar global (`extern s32 X;`) is assumed not to alias struct fields, so GCC keeps
  the stack top in a register. If the target re-loads 0x180 after the global store, declare the global as an
  array (`extern s32 X[];`, store to `X[0]`). (func_001DAF98)
- Prototypes change scheduling: implicit declarations (func_001ED878, func_00177908) gave wrong instruction order
  or a regswap. Adding `void f(s32);` fixed func_001CF940 and the JP "Regswap" nonmatch func_001DD620.
- Read-modify-write of the stack top value: write the full `arg0->unk_174[arg0->unk_174[3] + 4]` on both sides.
  A `s32* p = &...` temp gives swapped addu operands. (func_001DD288, func_001D5DC8)
- `top--` folded into the index (`unk_174[unk_174[3]-- + 4]`) matches when the target computes the address from
  the old top and stores top-1 before the use (func_001CFD58). When the target loads 0x180 directly and not
  through an `addiu a,a0,0x180` pointer, use separate statements, with an f32 temp if a float store must come
  after the `sw` (func_001D40B0).
- Field at Script+4 is a pointer to an object (actor?): `*(u8**)&arg0->unk_00[4]`. Writing that expression in
  both the test and the use (no temp) gives the `addiu a2,a0,4` base the target uses (func_001D6B50).
- Script fields used past the header's struct: 0x2F4 (f32), 0x31C/0x320/0x324 (s32), 0x328 (u64 flags),
  0x330 (f32). unk_174[36] (0x204) holds an index into D_00388CC4 (only when >= 0x800).
