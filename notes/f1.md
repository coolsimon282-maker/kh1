## Rules found (23 Nov, f1)

F1. **Defining one function in C can change a DIFFERENT, already matched function far away in the same file, with
    no call relation at all** (func_0013C548 at line 740 broke func_001560F8 at line 3308: combine stopped folding
    `sb $0,D_00550400+3($3)` and the function grew 8 bytes, shifting everything after it).
    The RTL before combine is identical; which way it goes flips with ANY extra declaration anywhere above
    (`extern int dummy;` flips it, blank lines don't), so it depends on the compiler's memory layout
    (ee-gcc 2.96 leaves rtx fields uninitialised / hashes by pointer), not on the C of the victim.
    How to find the victim: keep the bad build's map, build the clean tree, `diff` the two
    `build/fm/SLPS_251.98.map` files: the first function symbol whose address moves comes right after the victim.
    Fix: express the same thing with a different set of declarations. Here: instead of an extra
    `s32 f_r(...) __asm__("f")` alias, change the file's real prototype of the callee to return s32
    (one declaration less; the other caller still matched). If nothing natural works, any extra harmless
    declaration above the victim flips it back.
    Scripts: fable-work/chk60f8.sh (grep one instruction in the compiler output), dump.sh + fx.sh (per-pass RTL
    dump of one function, good vs bad).

F2. **Walking pointer and base pointer in each other's registers (base stays in the parameter's register, the
    walker gets a new one, loop counts DOWN 9..0 with bgezl): write the loop as an index loop, not a pointer walk.**
    `p += off; for (i = 0; i < 10; i++) if (*(s32*)(p + i*4 + 8) - *(s32*)(p + i*4 + 4) > 0) f(p + *(s32*)(p + i*4 + 4));`
    The compiler makes the walking pointer and the down-counter itself (strength reduction), and then the base keeps
    its register. A hand-written `e = p; ... e += 4` with `for (i = 9; i >= 0; i--)` gives the swapped registers.
    Also fixed the load order (`lw 0x10` before `lw 0xC`): write the condition with both loads spelled out
    instead of a saved `off` variable. Proven by func_001560C8.

F3. **THE MECHANISM BEHIND RULE 1 (bne vs bnel next to a call) is "cannot throw", and it can be switched on
    from a declaration: `NOTHROW(void, callee);` (macro in include/common.h).**
    ee-gcc 2.96 sets TREE_NOTHROW on a function after compiling its body (if nothing in it can throw), and every
    later call to it in the file gets a `REG_EH_REGION 0` note (visible with -dr: the call to a C-defined callee
    has `(expr_list:REG_EH_REGION (const_int 0))`, a call to a declared-only one has no note = "may throw").
    Reorg treats the two differently, hence plain vs likely branches around the call.
    Consequences:
    - What the callee's body contains does not seem to matter (C has no exceptions, so every compiled body gets
      the flag): func_00218DD0 calls into other files and its caller func_002190C0 still wants it flagged.
    - Target plain, callee in ANOTHER file (the split is finer than the original source) or still INCLUDE_ASM:
      write `NOTHROW(void, callee);` instead of its prototype. No need to match the callee first.
      It is an `extern inline` dummy body (compiled far enough to get the flag, never emitted) with an old-style
      `double` parameter so that inlining fails at each call and a normal `jal` is emitted.
      Not for callees with float arguments (no prototype = promoted to double).
    - A likely branch in the target does not prove the callee was unflagged: func_002479A0 keeps its one
      `beql` with every callee NOTHROW. So when unsure, flag all callees that sit at lower addresses in the
      same original file and see.
    Proven by xpackage func_00247A30 and func_002479A0 (a3/a4 "known reorg beql-vs-beqz problem"); their callees
    live in src/xmonitor.c, so xmonitor.c and the start of xpackage.c were one source file originally.
    Also xpotato func_002190C0 (task E) without matching func_00218DD0 first.

F3b. **NOTHROW_FN(prototype): the same flag with a real prototype, for callees with float arguments.**
    `NOTHROW_FN(s8 func_0018B5E8(s16 a, f32 b));` (include/common.h) compiles an empty WEAK copy of the callee
    into the section `.nothrow_dup`; the linker script discards every section it does not place, and the real
    function from the other file is what gets linked. Only for callees in another file (a callee that is
    INCLUDE_ASM in the same file would be defined twice: use NOTHROW there).
    This solved the whole "pppSRand epilogue" family (a2/a3/a5/a6: target `bnez` + `ld s0`, ours `bnezl`):
    the six pppSRand*CVCalc functions call the two helpers that sit just BEFORE them in memory, which the split
    put at the end of the previous file. So the original file was: helper, helper, Calc - the split of the
    whole pppSRand/pppRand group is shifted by two functions (worth fixing in the yaml one day; then the
    NOTHROW_FN lines go away).
    How to spot it: the unmatched function calls functions with slightly lower addresses that are defined in
    a different src file.

F4. **Search loop whose bound is loaded into $2, tested, then COPIED to another register for the loop
    (`lw $2,N; blez $2; daddu $7,$2`), where `break` gives the bound loaded straight into $7: leave the loop
    with `goto found;` (label right after the loop) instead of `break`.** Proven by func_0011D028.
    Same function: three stores after the loop came out in the target as offsets 0, 8, 4 (last in the `jr`
    slot); the source order that gives it is 0, 4, 8 (the constant store last). With only three stores, try all
    six orders before anything else.

F5. **Both an argument register AND a copy of it are used (`daddu $3,$6` at the top, compares use $3, the
    call still gets the untouched $6): the callee takes that parameter too.** Rule 2 for a later argument:
    func_00171E50 calls func_00157A30(a0, 0x1A, a2) (three parameters; check the callee's own prologue for
    `daddu $sN,$6`). Written as `u8* p = a0; u8* q = a2; if (q && p != q && x == q) f(a0, 0x1A, a2);`.

F6. **One bit of a u64 tested with `ld; dsrl32; andi 1; sltiu r,x,1` (ours: `xori 1; andi 1`): read it as a
    32-bit-typed bitfield inside the 64-bit word**: `struct { u64 lo:42; u32 b:1; }` and `r = !s->b;`.
    A `u64 b:1` or `u8 b:1` field, shifts and masks, temps and `== 0` all fold to xori or add a sign-extension
    pair. Proven by func_001532C8.

F7. **A float zero loaded once into a register and stored twice (`mtc1 $0,$f2; swc1 $f2,A; swc1 $f2,B`) where
    two separate `= 0.0f` give `sw $0`: chained assignment `b.w[0] = b.w[2] = 0.0f;`** (the first-named
    field is stored second in the source sense, but both use the register). Statement order then decides the
    rest; func_0015DC50: `b.v[1] -= y; b.w[0] = b.w[2] = 0.0f; b.w[1] = y; b.w[3] = 1.0f;`.

F8. **`addu` with the operands the other way round for an array element address (target `addu r, index, base`,
    ours `addu r, base, index`; a1's "one addu operand order away" list): access the global DIRECTLY
    (`D_003854E0_view.b4[k] = 0;`), not through a local pointer (`g = &D; g->b4[k]`).** With the global named
    in the expression, the address is `index + constant symbol` when the RTL is made (constant last), and the
    symbol only later becomes a register, keeping second place. A pointer variable is a register from the
    start and goes first. For a struct that has no suitable field layout yet, declare a view of it:
    `typedef struct {...} View; extern View D_view __asm__("D_003854E0");`.
    Proven by xhumungus func_001CC950, func_001CC618, func_001CCA88 (all three matched at the first try this way).

F9. **First call of an iterator with a literal 0 (`daddu $4,$0,$0; b <call>`), `move a0,s0` in the branch-likely
    slots, `jal` with a nop slot: `for (p = f(NULL); p != NULL; p = f(p))`** - two call sites that the compiler
    merges. `p = NULL; while ((p = f(p)) != NULL)` gives `move s0,zero` + `move a0,s0` instead. (func_001D8500)

F1b. **More on rule F1 (xhumungus).** xhumungus has at least 8 matched functions that flip like this
    (func_001DB7A8, fm_func_001DC9A0, func_001D0438, func_001D04C0, func_001D0548, func_001D0590, func_001D0600,
    func_001D0828: all `GLOBAL[index] = value` or `*GLOBAL[index] = value`, 4 bytes longer when it goes wrong).
    What I measured: which way they go depends on the CODE of functions compiled earlier in the file - every
    source form of a new function that compiles to the same code gives the same result, declarations, labels,
    extra locals and blank lines change nothing there, and many simple functions in between do not reset it.
    It is not a parity: each of func_001CC950 / func_001CC618 / func_001CCA88 alone breaks six functions, any
    two or all three together break none.
    Working method: keep each candidate's C in its own file and try subsets -
    `python3 fable-work/combo.py xhumungus func_A=fable-work/a.c func_B=fable-work/b.c` writes the file,
    `bash wsl-build.sh bash fable-work/chkxh.sh` (20 s) lists the already-matched functions whose size changed
    (needs a reference list from a good build: see the script). Commit a subset that lists none.

F10. **Small things the local model's give-up list in seg_132D60 turned on** (16 functions, all first or second try):
    - `ldl/ldr/sdl/sdr` + `lw/sw` for 12 bytes: a struct assignment `D.v = *a0;` where the struct is three
      32-bit members (4-byte alignment). They are NOT hand-written.
    - two stores into one global struct coming out in the wrong order: swap the two statements (the LAST
      statement's store goes first when both are ready; func_00246020, func_002485B8, and the two stack stores
      of func_00243630, where swapping `m.a = a0; m.b = a1;` also flipped the a0/a1 set-up before the call).
    - `GLOBAL[i] = x` with `lui $1; addu $1,$1,i; sw x,%lo(GLOBAL)($1)`: plain `extern T GLOBAL[]; GLOBAL[i] = x;`.
    - `addu r, base, index` (base first) for `p->e[p->n] = v`: a struct with the array member
      (`struct { s32 n; s32 e[1]; }`), not `p[p[0] + 1]` (which gives index first).
    - `move v0,zero` both in the branch slot and after the call: early return
      `if (x == 0) return 0; f(); return 0;`.
    - `&TABLE[cond]` computed without a branch (`xori; sltu; sll 4; la; addu`): put the condition in an
      `s32 i = (f() != 1);` first, then `return TABLE[i].v;`.
    - a callee that takes a parameter although its existing prototype says `(void)` and the caller passes its
      own a0 through: define it old-style (`s32* f(a0) u8* a0; {`) and make the later extern `f()`.
