# Notes: Fable agent, workspace f3 (hard tier)

## Rules found (23 Nov, f3)

G1. **"Pointer-copy chains" (`daddu $9,$3; daddu $10,$9; daddu $6,$10 ...`, a fresh copy of the same address
    for every element stored/loaded; a3's family func_00108970 / func_00108B60 / func_00108CF8 / func_001807B0 /
    func_0011A728): an ARRAY THAT IS A STRUCT MEMBER (or a global array), indexed with a VARIABLE, then a
    constant sub-index, written out element by element.**
    `typedef struct { s32 v[4]; s32 pad[20]; } E; typedef struct { E e[1]; } T;`
    `a0->e[a1].v[1] = D_2d[a2][1];` (D_2d declared `s32 D[][4]`), one statement per element.
    Each such access (variable offset + non-zero constant offset inside a struct) makes the compiler put the
    address in a new register, and those copies survive. Pointer arithmetic (`a0[a1].v[1]`, `p = &a0[a1]`,
    `*d++ = *s++`, struct assignment, inline helpers) never gives the copies.
    The first element (offset 0) comes out as `addu r, base, off`, the later ones as `addu r, off, base`.
    Proven by func_00108970, func_00108B60 (index from a global: `s32 i = D;` local, `a1->e[i].m[3][1] = ...`),
    func_00108CF8 (`D_00494D80[a1].t.unkC0 = a0;` + `&D[a1]` passed on).
    In a loop the same source gives the "store pointer biased by +0x4C" form instead (func_001089F8).
G2. Zeroing/initialising many globals where 2-element arrays have their [1] store early and [0] store at the
    very end of the function: just write everything in natural address order (func_00229850).
G3. ppp files with soft-double calls (`jal atan` / `jal dpadd` with a FILLED delay slot where ours has `nop`):
    the file has to be in NO_G_FILES in configure.py (then `agent-tools.sh configure`). func_0018FE28 was the
    twin of draw.c's func_001AADC8 all along.
G4. TOOLS: fable-work/tv.sh <file> <func> <variants.txt> tries many variants (separated by `====` lines), each
    applied by fable-work/ap.py on top of the committed file plus the functions already matched in this batch
    (fable-work/ok/<file>.txt), so nothing is dropped. fable-work/base.sh <file> refreshes the committed copy.
