## Things learned

* **The scratchpad folder is shared with other agents**: keep sandbox files in your own subfolder, never
  in its root (my first `cc.sh`/`t.c` there were overwritten mid-session).
* **Sandbox compile.** Compiling a test .c directly in the WSL mirror is much faster than a full build and
  shows the exact output (`-O2 -G0 -g -DVERSION_FM`, piped through `tools/masps2.py`):
  `cd ~/kh1-build-a4 && tools/cc/ee-gcc2.96/bin/ee-gcc -c -B tools/cc/ee-gcc2.96/bin/ee- -Iinclude -isystem include/sdk/ee -isystem include/gcc -DVERSION_FM -O2 -G0 -g _t.c -S -o - | python3 tools/masps2.py`.
  Put many variants (or all permutations of a statement order) in one file and grep the result.
* **masps2.py always adds a `nop` after `mfc1`, `c.le.s`/`c.lt.s`, and after `mtc1` followed by a float op.**
  FM's own code often has no nop there (e.g. float->int `cvt.w.s; mfc1; sll`), so those functions can't match
  with the current tool chain. Check the target for `mfc1` followed directly by another instruction before
  starting one. (Seen in: fm_func_00111BE8, func_0018B5E8, func_00189F20, func_0018A680.)
* Store order: gcc schedules `a=0; b=0;` as `sw b; sw a` (last one first, the rest in order, the first ends
  in the delay slot). Chained `a = b = c = 0.0f` gives `s.s a` first, then the rest from the end backwards.
* `x % C` after an unused `x / C` (hours/minutes/seconds from a frame count) leaves a dead `move` of the
  divisor: that's how fm_func_00111B48/B90 matched (compute the unused quotient too).
* Loop with a pointer reloaded every iteration plus a reversed counter: write the offset as its own
  variable (`ofs += 2`) with a `u8*` base (func_00128DC0).
* gcc's own delay-slot choices in the `-S` output don't matter (the assembler redoes them), but branch-likely
  (`bnel`) does: if the target has `bnez` + a load in the delay slot where gcc gives `bnel`, no loop form
  tried changes it (func_001C1AE0).
* A `void` function ending in a call always becomes a tail call (`j`); a target with `jal; nop; ld ra; jr`
  needs something else (not found: variadic, struct return, u64 return all still tail-call or differ).
* `((Vec*)&D->unk_10 + i)->x` (pointer arithmetic on a cast) gives `addu v0,a0,v0; lwc1 0x10(v0)`, while
  `D->vec[i].x` gives `addu ...,16` separately (func_001113A8).
* **Second run.** The sandbox command needs `MASPS2_NO_NOPS=1` in front of `python3 tools/masps2.py` now
  (FM is built without the hazard nops). Old 32-bit gcc can't read files on /mnt (`Value too large`): copy the
  test file into `~/kh1-build-a4` first. Remember the `-S` text is before the assembler fills delay slots: a
  `jal f; li $2,1` there is `jal; nop; li` in the object.
* **Variable reuse decides register allocation.** func_001AAA30 only matched when the pointer parameter was
  reused for the flags (target keeps both in `$16`); func_001AAFC0 (ray/sphere) only matched when the dot
  products were accumulated with `+=` into the variables, and `c = -b; b = a * 2.0f;` reused them before the
  branch (the target has those in `$f20`/`$f21` across the sqrt call).
* **A variable set in only one branch** (func_001AC180's `data`) explains a callee-saved register that is only
  written inside an `if`.
* **Reloads after a store** need the field to have the same type as the stored one (DrawNode `link`/`linkPrev`
  both `DrawNode*`, so the `if (a->x) a->x->y = ..; ..->next = a->x` pattern reloads).
* **Operand order in compares/multiplies** shows in the diff as `r` lines: `bne a3,v0` vs `bne v0,a3` means
  swap `x == y`; `mult v0,a0,v0` means swap the factors.
* **Loops that walk `p = &arr[i]` inside a `for (i...)`** give the target's `move q,p ... addiu p,q,4` pair
  (func_00111328); `p++` in the for header does not.
* Calls to the K&R-style `fm_func_00111B10(void)` helpers with an argument: cast the function
  (`((u32 (*)(s32))fm_func_00111B10)(t)`), same code.

## Third run: the ppp code was compiled WITHOUT strict aliasing

**Finding:** the ppp library (`src/ppp/**`) matches with `-fno-strict-aliasing`. Several functions I had given
up on, all in ppp/, match with plain natural C when compiled with that flag, and none of them match without it
(the target reloads a pointer/global after a float or byte store that strict aliasing says can't touch it).
I checked every `src/ppp/**/*.c` (all functions matched so far): `gcc -S` output is identical with and
without the flag, so adding `-fno-strict-aliasing` for `src/ppp/` files in configure.py is safe. (I can't edit
configure.py; the lead should.) Sandbox: add `-fno-strict-aliasing` to the compile command in notes above.

## Third run: other things learned

* **Comparator script**: `cmp.py` in my scratch folder (normalizes the target .s and gcc -S output, expands
  `li.s`, `dli`, `la sym(reg)`) plus generating every statement order with Python and compiling them all in one
  file found most of this run's matches (store orders of 5-9 statements; 5040 variants compile in ~6 s).
* **A load of a global after a store to the same global**: `x = D[0]` right after `D[0] = 0.0f` is reloaded
  (`sw $0` then `lwc1`), xpeanut func_001255F8.
* **xpackage table**: FM's code reads `D_00669A18` (in undefined_syms_auto) for JP's `D_00663A28`; I added
  `XPACKAGE_TABLE` (#ifdef VERSION_FM -> D_00669A18) in xpackage.c, which unblocked func_00247D90/DC8/FE8,
  func_00248168.
* `u128` values: `u_long128` (from sdk eetypes.h). A constant tag `x = 0x70000006` gives FM's `por; lui; ori`.
* `(f32)u32` + branch: gcc puts the `cvt.s.w` before the `b` (not in its delay slot) where FM has it in the
  delay slot, so fm_func_00111BE8 still fails (8 bytes longer). Probably needs a tool fix (masps2/as delay
  slot filling after mtc1). C that is otherwise right is in the give-ups.
* `if (a) {..} if (b) {..}` with calls: gcc picks `beql` for the 2nd test where FM has `beqz` (func_002479A0,
  same as func_00247A30/func_00111198). Not solved.
