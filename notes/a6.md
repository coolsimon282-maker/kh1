# a6 notes (Final Mix matching)

## Learned
- Strict aliasing is on: a load of a pointer-typed field is scheduled before a store through `s32*`.
  If the target keeps the load after the store, give the field an `s32` type (cast at use).

- Store order: several stores to one base often come out "last statement first, then the rest in order"
  (x=..;y=..; -> y,x; a,b,c -> c,a,b). `x = y = z = 0` runs z,y,x -> asm x,z,y. Pick the source order
  from the asm with that rule.
- `return (x & 1) != 0;` folds to `andi` only; the target's `andi + sltu` came from
  `if (x & 1) { return 1; } return 0;` (xsauce func_0010CCD8).
- A global accessed as `lui; addiu %lo; sw 0(reg)` even when used once = the variable is `volatile`
  (xarcade D_00495160 / D_00495164 are `vs32`).
- Address arithmetic: `(u8*)(base + idx * 4)` written once per use (no local pointer) kept
  `addu idx,idx,base` operand order (xkinetic func_001C3680).
- Loops are unrolled when the trip count is a small constant.
- xkinetic: Script (xhumungus.h) is a stack VM: 0x180 sp, 0x184 stack[], 0x208 var[], 0x270 another
  array, 0x2F0. Added a local `ScriptVM` overlay in xkinetic.c; indexing `unk_174[arg1 + 37]` gets
  CSE'd into a wrong base, the overlay matches.
- xgoblin: func_0011F980 builds a GIF tag (SCE_GIF_SET_TAG(qwc, eop, 0, 0, 0, 1), A+D), func_0011F9B0 a
  DMA tag (qwc | id << 28, bit 63 when the address is scratchpad >= 0x70000000). The 2nd arg must be
  s32 (not u64) to match.
- xsauce FM func_0010F3B8 takes a 3rd arg; FM-only globals D_004D5AF8/D_004D5AFC come from
  undefined_syms_auto (just `extern` them).
- ppp Con functions: `&pobj->val[ctbl->useVal[n]]`; when a byte store comes first, load every val
  pointer at the top (char stores alias everything).

## Second run (a6)

### Learned
- `if (x & C) return 0; return 1;` in a `static inline` helper, called as `ret = 0; if (c) ret = helper(p);`,
  gives the target's `lui/and/sltiu` (xtoaster func_001233D0, func_001237E8). Plain `!(x & C)` gives sra/xori/andi.
- A u64 compare result stored in an s32 adds `dsll32/dsra32`; declaring the function and `ret` as `s64`
  removed it (xtoaster func_00123518).
- Loop-invariant constants: a `(x >> 37) & 3` written twice inside a loop puts 3 in a saved register;
  moving the expression into a `static inline` function keeps `andi` immediates (xtoaster func_001235B8).
- `while ((p = next(p)) != NULL) { if (..) return p; } return NULL;` matches the search loops; `break` +
  `return p` does not.
- Global address computed into s0 before calls, then `sw v0,0(s0)` after = a local pointer variable
  `s32* p = &global;` set at the top (xgoblin func_0011F8C0). `volatile` gave the address after the calls.
- Short loops get padded with nops (R5900 short-loop fix) by the compiler: plain C is fine (xsauce strlen).
- `x = y = ... = 0.0f` chain: asm order = first target, then the rest from the last to the second
  (pppKeMdlTfdUv2Con).
- FM-only names: when a shared INCLUDE_ASM uses FM symbol names that JP's C doesn't have (D_004E44C0...), wrap
  the C in `#ifdef VERSION_FM` with FM `extern`s and keep INCLUDE_ASM in `#else`.

### Structures

  flags), 0x3A8 bitmask, 0x006 type byte (2, 9, 10).

## Third run (a6)

### Learned
- **Union access = alias set 0.** gcc 2.96 gives any access through a union member alias set 0 (conflicts with
  everything). When a strict-aliasing file needs a reload/order that only `-fno-strict-aliasing` gives, access
  that one field through a one-member union: `((XGoblinAny*)g)->g.unk_08` (xgoblin func_0011EEB8: list head
  loaded after the stores to the new entry), `((XToasterAnyF32*)&t->unk_44)->f = x` (xtoaster func_00123350:
  unk_130 reloaded after the float store). Both matched in the sandbox with -fno-strict-aliasing as plain C,
  so xtoaster/xgoblin may really have been built without strict aliasing too.
- `ppvMng->stop || ppvMng->unk_B4 != 0` compiles to `ld 0xB0; and 0xFF0000FF00` (gcc merges the byte tests);
  copy pppAccele's C (pppSclAcceleCalc, pppKeThTpCalc).
- A call that seems to have one arg but the target never touches $5 before `jal`: the callee takes the caller's
  2nd arg straight through (`func_0019FF38(&val[...], p)`, pppRyjMegaPlace{Lamp,Model}Calc). Check the callee.
- Offset form: target `idx*0x74; addiu 0x30; addu base; lw 8()` came from `o = i * sizeof(E) + 0x30;
  ((E*)(base + o))->f` (xtoaster func_00124CD8); a pointer reloaded every loop pass came from reading it as
  `*(s32*)&D_003010F8` (an s32 load aliases the s32 store).
- `(&arr[0].field)[i * (sizeof(T) / 4)] = 0` gives `la base+field; addu 95*size` (count-down store loop,
  func_00124F38); `arr[i].field` gives `la base; addu 95*size+field`.
- Store forwarding: `a = v->ang; v->ang.x = w->x; a.x -= v->ang.x;` reuses the loaded register (CSE knows the
  stored value); `a.x -= w->x` reloads (pppKeMatSNCalc).
- s8/s32 from float: plain casts give cvt.w.s now (pppRandIV/RandUpCV/SRandUpCV helpers, func_001A0EA8).
- Names: FM asm uses JP names where jp_names.txt has them (D_003010F8 is at 0x304BE8 in FM); otherwise FM
  addresses (D_002BC140, func_00122130 in xarcade).
- xtoaster: 3 XToaster* slots at D_002E26A0 (right after the 96-entry array; `XT_SLOTS` cast), cursor
  `XToaster* D_002E26AC`. D_003010F8 + 0x30: 10 party entries of 0x74, flags at +8.
- xgoblin: pool header {u16 size, u16 count, base, list head (unk_08), cursor (unk_0C)}; func_0011EE10 finds a
  free entry, func_0011EEB8 allocates and links by priority.

### Learned
- **No tail call**: `s32` return type + ONE `if (all conditions && ...) { call(); }` with no early `return;`
  gives `jal ...; ld ra; jr` (pppKeBornRnd2Calc). `void`, or `s32` with early `return;`s, still gives `j`.
- **MMI/VU0 colour sequences** (`pextlw/pextlh/qmtc2/vitof0/vmul/vftoi0/psrlw 7/ppach/ppacb`) match as a
  `static inline` with `__asm__ volatile` using hard-coded `$2`/`$3` and clobbers `"$2","$3"`; inputs are the

- `tgt = cond ? a : b;` (ternary) gave the `beq; addu(delay); b; addiu` shape the if/else didn't, when the
  if/else let CSE forward a stored float into the next call's argument (pppRandUpCVCalc).
- `addu idx8, base` operand order: `pppShapeSt* st = &ppvEnv->lpShape[i]; shp = st->shape;` gives
  `addu base, idx8`; `ppvEnv->lpShape[i].shape` gave the other order (pppDrawShapeXCalc).
- A store scheduled *after* a following byte load: read the byte into a local before the store
  (`flag = e->flag & 0x80; v->wait = 0; if (flag) ...`).
- Register swap between two `&pobj->val[useVal[n]]` locals: swap their declaration order.
- `lui %hi(D_X+0x10)` with `D_X+0x10 - 0x10` in another register: the source uses one matrix `D_X` (here
  D_00616000, rows 1-3 show up as D_00616010); declare `extern sceVu0FMATRIX D_00616000;`.

  large"); my script: scratchpad a6x/cc.sh + f.sh (filters the noise).
