# a6 notes (Final Mix matching)

## Learned
- Strict aliasing is on: a load of a pointer-typed field is scheduled before a store through `s32*`.
  If the target keeps the load after the store, give the field an `s32` type (cast at use).

- Store order: several stores to one base often come out "last statement first, then the rest in order"
  (x=..;y=..; -> y,x; a,b,c -> c,a,b). `x = y = z = 0` runs z,y,x -> asm x,z,y. Pick the source order
  from the asm with that rule.
- `return (x & 1) != 0;` folds to `andi` only; the target's `andi + sltu` came from
  `if (x & 1) { return 1; } return 0;` (xsauce func_0010CCD8).
- A global accessed as `lui; addiu %lo; sw 0(reg)` even when used once = the variable is `volatile`
  (xarcade D_00495160 / D_00495164 are `vs32`).
- Address arithmetic: `(u8*)(base + idx * 4)` written once per use (no local pointer) kept
  `addu idx,idx,base` operand order (xkinetic func_001C3680).
- Loops are unrolled when the trip count is a small constant.
- xkinetic: Script (xhumungus.h) is a stack VM: 0x180 sp, 0x184 stack[], 0x208 var[], 0x270 another
  array, 0x2F0. Added a local `ScriptVM` overlay in xkinetic.c; indexing `unk_174[arg1 + 37]` gets
  CSE'd into a wrong base, the overlay matches.
- xgoblin: func_0011F980 builds a GIF tag (SCE_GIF_SET_TAG(qwc, eop, 0, 0, 0, 1), A+D), func_0011F9B0 a
  DMA tag (qwc | id << 28, bit 63 when the address is scratchpad >= 0x70000000). The 2nd arg must be
  s32 (not u64) to match.
- xsauce FM func_0010F3B8 takes a 3rd arg; FM-only globals D_004D5AF8/D_004D5AFC come from
  undefined_syms_auto (just `extern` them).
- ppp Con functions: `&pobj->val[ctbl->useVal[n]]`; when a byte store comes first, load every val
  pointer at the top (char stores alias everything).

## Second run (a6)

### Learned
- `if (x & C) return 0; return 1;` in a `static inline` helper, called as `ret = 0; if (c) ret = helper(p);`,
  gives the target's `lui/and/sltiu` (xtoaster func_001233D0, func_001237E8). Plain `!(x & C)` gives sra/xori/andi.
- A u64 compare result stored in an s32 adds `dsll32/dsra32`; declaring the function and `ret` as `s64`
  removed it (xtoaster func_00123518).
- Loop-invariant constants: a `(x >> 37) & 3` written twice inside a loop puts 3 in a saved register;
  moving the expression into a `static inline` function keeps `andi` immediates (xtoaster func_001235B8).
- `while ((p = next(p)) != NULL) { if (..) return p; } return NULL;` matches the search loops; `break` +
  `return p` does not.
- Global address computed into s0 before calls, then `sw v0,0(s0)` after = a local pointer variable
  `s32* p = &global;` set at the top (xgoblin func_0011F8C0). `volatile` gave the address after the calls.
- Short loops get padded with nops (R5900 short-loop fix) by the compiler: plain C is fine (xsauce strlen).
- `x = y = ... = 0.0f` chain: asm order = first target, then the rest from the last to the second
  (pppKeMdlTfdUv2Con).
- FM-only names: when a shared INCLUDE_ASM uses FM symbol names that JP's C doesn't have (D_004E44C0...), wrap
  the C in `#ifdef VERSION_FM` with FM `extern`s and keep INCLUDE_ASM in `#else`.

### Patterns learned
- **Callee defined in the same file with a return value, result unused**: the caller's register choice
  changes (`$3` instead of `$2` after the call). Call it through a void alias:
  `void func_0011C7A8_v(...) __asm__("func_0011C7A8");` (func_0011E4D0, func_0011E480, func_0011D4B8).
  Same for an SDK prototype: `sceGsSyncPath` must return s32 (func_00106948).
- **`jalr` with `addiu $2,$0,4` in its delay slot and the value returned afterwards** = `if (fp) fp(); return 4;`
  with a *void* function pointer (gcc's reorg moves the `li` into the call slot) (func_0011CBA0).
- **`lui; addiu; lw 0(reg)` for a single read of a global** = the global is `volatile` (D_002BBDE0,
  func_0011DC98/0011DC28).
- **lq/sq through `$6` + a `nop` before `jr`** = inline-asm sceVu0CopyVector in a static inline helper
  `asm volatile("lq $6,0(%1)\n\tsq $6,0(%0)\n\tnop" :: "r"(dst), "r"(src) : "$6", "memory")`
  (Seg150D8_CopyQ, func_0011A758/0011A9C8). Calling the helper (not writing the asm inline) fixed the reg order.
- `(x >> 4) & 0xF` on a u32 field became `lbu + dsrl`; a bitfield view `struct { u32 b0:4, b4:4, rest:24; }`
  gave the target `lw; srl; andi` (func_00105B68). For bits 11+/18+/22+/28+ plain `(u32)x >> n & m` works.
- Stores of one value to s16 and s32: `m = -1; *(s32*)(p+0x34) = m; *(s16*)(p+0x30) = m;` (order reversed
  in the output) (func_00118548).
- Float constants: gcc here sometimes lands 1 ulp low on the exact decimal; use a decimal between the wanted
  float and the next one up (0x3F199999 = `0.59999998f`, 0x3E999999 = `0.29999998211860657f`,
  0x3E647FBE = `0.22314355f`).
- `D[0] = D[1] = D[3] = 0.0f; D[2] = x;` gave the store order 8,0,C,4 (brute force over chain orders).
- `if (f() != 0) { if (g() != 0) return 1; } return 0;` keeps the `bne; li 1; li 0` shape (`&&` gives sltu).
- Loops: `do { ... p++; } while (--n);` inside `if (n > 0)` gave `blez` + `bnez n` count-down (func_00105510);
  a search loop `for (...) if (x) break;` followed by stores came out right as `i = 0; do { if (..) break;

- Offsets 4 and 0 from a 0x40-stride table: `p = D[i]; *(T*)(p + 4)` keeps base = symbol (pointer walking
  biased it by +4) (func_00150D70).
