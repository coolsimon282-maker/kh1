# a6 notes (Final Mix matching)

## Learned
- Strict aliasing is on: a load of a pointer-typed field is scheduled before a store through `s32*`.
  If the target keeps the load after the store, give the field an `s32` type (cast at use).

- Store order: several stores to one base often come out "last statement first, then the rest in order"
  (x=..;y=..; -> y,x; a,b,c -> c,a,b). `x = y = z = 0` runs z,y,x -> asm x,z,y. Pick the source order
  from the asm with that rule.
- `return (x & 1) != 0;` folds to `andi` only; the target's `andi + sltu` came from
  `if (x & 1) { return 1; } return 0;` (xsauce func_0010CCD8).
- A global accessed as `lui; addiu %lo; sw 0(reg)` even when used once = the variable is `volatile`
  (xarcade D_00495160 / D_00495164 are `vs32`).
- Address arithmetic: `(u8*)(base + idx * 4)` written once per use (no local pointer) kept
  `addu idx,idx,base` operand order (xkinetic func_001C3680).
- Loops are unrolled when the trip count is a small constant.
- xkinetic: Script (xhumungus.h) is a stack VM: 0x180 sp, 0x184 stack[], 0x208 var[], 0x270 another
  array, 0x2F0. Added a local `ScriptVM` overlay in xkinetic.c; indexing `unk_174[arg1 + 37]` gets
  CSE'd into a wrong base, the overlay matches.
- xgoblin: func_0011F980 builds a GIF tag (SCE_GIF_SET_TAG(qwc, eop, 0, 0, 0, 1), A+D), func_0011F9B0 a
  DMA tag (qwc | id << 28, bit 63 when the address is scratchpad >= 0x70000000). The 2nd arg must be
  s32 (not u64) to match.
- xsauce FM func_0010F3B8 takes a 3rd arg; FM-only globals D_004D5AF8/D_004D5AFC come from
  undefined_syms_auto (just `extern` them).
- ppp Con functions: `&pobj->val[ctbl->useVal[n]]`; when a byte store comes first, load every val
  pointer at the top (char stores alias everything).
