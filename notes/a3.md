# Agent a3 notes (Final Mix)

## Tooling facts learned (important for everyone)

* **FM was assembled without the hazard nops that `tools/masps2.py` inserts.** In FM asm, `mfc1` is never
  followed by a nop, `c.lt.s`/`c.le.s` are followed directly by `bc1t/bc1f`, `mtc1`/`li.s` are followed
  directly by an FPU op or `swc1`. masps2.py always adds nops there (JP needed them), so **any FM function
  with mfc1, c.lt.s, c.le.s, or mtc1/li.s followed by a float op cannot match with the current tools**.
  That's why many JP-matched float helpers are `#ifdef VERSION_FM INCLUDE_ASM` (e.g. xball func_00121970).
  Skipped for this reason: pppRandUpIV func_00189D70, pppSRandHCV func_0018B7F8, pppRandDownCV
  func_0018A4A8, pppSRandDownFV func_0018AFB8, pppDrawMdlLoop func_0018C818, xtailor fm_func_00110068,
  xapple func_0013BAC0, pppRyjDrawMatrixWorldDttFr func_001A3FE0, xball func_00120F78/func_00121970.
* `diff <func>` compares by address in the current build, so if any earlier function in link order differs
  in size, everything after it shows as different. When testing many functions in one build, compare each
  function against the original by its own start address (I used a small script that reads the built rom at
  the symbol address from `nm` and the target rom at the address in the .s file, masking %hi/%lo/jal fields).
* Fast iteration without a full build: run the game compiler on a temp copy of the C file in the WSL mirror
  (`~/kh1-build-<agent>`), the 32-bit cc1 can't read /mnt/* files, so copy the file into the WSL home first.
* Store order: gcc's scheduler tends to move the *last* store of a run up to the front. For
  target order `A B C` write `B C A`... in practice: write stores in natural/ascending order first and
  look at the result.
* C-defined bss arrays in a file (e.g. `ppvmng D_00360600[0x100]` in pppMngr.c) are NOT placed at the FM
  address. For FM code use the FM symbol from the asm as `extern` (e.g. `extern PppMngU D_00364130[];`).
* Pointer-typed stores alias pointer-typed globals: storing `NULL` through `void**` kept the `ppvMng` load
  after the stores (pppRyjMegaPlaceCon), while `u32`/struct-field stores let gcc hoist it.
* Unsolved pattern: `lui; addiu; sw $x, 0($reg)` for a single store to a global (xtailor func_00110230,
  func_0010FCF0, func_00110240). `volatile` gives the addiu form but then the store can't go in a delay slot.
  Plain/array/struct/float/initialized/static variants all fold to `sw %lo(sym)`. Still unknown.

## Second run (22 Nov)

### Big one: ppp code acts as if built with -fno-strict-aliasing

Many ppp targets keep a load after a store of a different type (float store then `pobj->time` reload; s32
store then pointer reload; float stack stores then s16 vertex loads). The build has strict aliasing on, so
make the accesses alias by hand:
* **union trick**: `typedef union { f32 f; s32 i; } FI;` and access the val area as `FI* v` / `v[0].f`
  (pppKeLnsLpSftCalc, pppDrawMdlTs3Calc; with a `void* p` member too for func_0018C818). For a stack vector
  passed to sceVu0ApplyMatrix: `union { sceVu0FVECTOR f; s16 s[8]; } v;` (pppVertexAttendCalc).
* **int typing**: write pointer fields as `s32` (`*(s32*)&v->lp = (s32)ptr`, a local struct with s32
  next/prev/owner for pppEMCB in pppFree).
Probably also true for xpotato (func_00218870 needed `s32 p[3]` to get a reload).

### Tools

My scratch scripts are in the scratchpad `a3/` folder: `cmp.py` (compile one src file in the WSL mirror
with the FM flags, compare named functions against the target .s by word, masking relocations),
`vary.py` (put `//VAR` in the C file where the function goes, write variants separated by `====` lines,
get a diff count for each in seconds), `show.py` (full side-by-side for one variant), `apply.py` (put a
variant in, wrapped in `#ifdef VERSION_FM ... #else INCLUDE_ASM #endif` or not), `bc.sh` (build and commit
only if the last line is `OK`; I once committed after a failing build because `| tail -1` hid the status).

### Other patterns

* **Jump tables**: FM has no `.rodata` split for most C files (config/kh.fm.yaml has `[0x390340, rodata]`
  for xpotato's area), so a `switch` that becomes a jump table fails to link (undefined `.L` labels from
  the rodata asm). Skip jump-table functions (`jtbl_` in the asm) until the yaml gets a split.
  (xpotato func_00218A38 / func_00218AC0: C is a trivial switch over XWhiskey fields 0,4,8,0x10,0x14,0x18,0x2C
  with `case 6: default:` sharing, matches byte-for-byte but can't link.)
* **`lui $1 / addu $1,$1,$reg / lw %lo($1)`** (gas macro with $at): gcc emits it for `array[i]` loads when
  the address isn't split; `p[i]` with a counter loop (instead of `*p++`) gave it in func_00215AF0.
* **Switch decision trees**: `slti x, 5` after `beq x,4` = cases 4 and 5 plus explicit lower cases sharing
  default (`case 0..3: default:`), on a *signed* switch value (`switch ((s32)u32var)`).
* **Compare order**: `if (a == b)` loads `a` second; swap operands when the two loads come out swapped.
* `lui/addiu/sw 0(reg)` for a single global store (xtailor func_00110230): an empty asm barrier
  `s32* p = &D; __asm__("" : "+r"(p)); *p = x;` reproduces it exactly; not committed (hack). volatile gives
  the addiu form but gcc won't put a volatile access in a delay slot, the target has it in one.

## Structs / names

* pppMngr: the ppvmng array is `D_00364130` in FM. `usef` at 0x86 is really u16 (lhu + andi 0xFFFF on
  `& 1` tests). Local struct `PppMngU` (in pppMngr.c) has usef/pEtc/unk_94 at the right offsets.
* pppMngr func_00185008 initialises a pppMemMng (include/ppp/pppEnv.h): lastFreeHeap=0, top=start,
  bottom=start+size-16, blocks are pppEMCB {next, prev, owner}.
* xpotato: FM's XWhiskey has an extra s32 at 0x2C (and munny moved to 0x24); accessed by offset cast.
* xowl: D_002C5C80 is an array of 31 entries of 0x40 bytes {s32 unk_00; s32 flags; ...}.

## Given up

* xtailor func_00110230 / func_0010FCF0: the lui/addiu/sw-0 pattern above.
* xtailor fm_func_00110068, pppDrawMdlLoop func_0018C818: masps2 nop after li.s / mtc1.
* pppMngr func_00185008 (heap init): everything matches except gcc loads the constant 1 early into $7;
  target uses $6 after the `sw a2,8(a0)`. Tried statement orders and local pointers.
* pppMngr func_001815A0 (set/clear stop bit 0x80 + unk_B7 for every active mng): target walks the array
  with a pointer at element+0xB0 (lhu -0x2A, lbu 1, sb 7); gcc always picks base+0 for me (tried ppvmng,
  PppMngU, a 4-aligned struct, a `u8* q = &m[i].drawPriority`). Logic is right, only the giv base differs.
* pppMngr func_00183658 (find free mng, test `*(u64*)(p+0x80) & 0x3000000000000`, init_part_mng, *out=p):
  target loop is NOT rotated (`b` to the test at the top, `i++` in the delay slot); every for/while form I
  tried is rotated by gcc.
* pppMngr pppFree: logic right (pppEMCB unlink/merge, allocSize -= blk->next - blk); target doesn't hoist
  the `blk->prev` load above the `allocSize` store, gcc does (type-based alias). Store order of the first
  two stores also differs.
* pppMngr dpd_set_shape_data / dpd_set_vsf_data: bit-per-entry loops (`if (!(i & 7)) bits = use[i >> 3];
  if (bits & 1) {...} bits >>= 1;`), targets D_00363930 (RendShape) / D_00363D30 (RendVsf). Target hoists
  `use + (i >> 3)`, `i++`, `i < n` above the branch and loads `*p` in the bnel delay slot; mine doesn't.
* ryjProg pppRyjMatrixWorldXYZCon (and the ZXY one): only diff is the register for &D_003701D0 after the
  pppGetRotMatrixXYZ call ($2 in target, $3 mine). Maybe the original had no prototype (implicit int).
* xball func_00121878 (FM): `li.s 1.0` followed by `swc1 $f0` -> masps2 treats $f0/$f1 as a pair, adds nop.
* xtailor func_0010F4A8 (FM), xbeginning func_00100168, xapple func_0013AB68: big FM versions of JP-matched
  functions; the JP C under `#else` is a good start, FM renames calls (e.g. JP func_001F9B50 -> FM
  func_001F9010, func_001F9F78 -> func_001F9438, func_001FD4C0 -> func_001FD100, func_001F2EF8 ->
  func_001F1ED8, func_00207640 -> func_00207748). Not tried yet.
