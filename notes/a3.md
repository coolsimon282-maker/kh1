# Agent a3 notes (Final Mix)

## Tooling facts learned (important for everyone)

* **FM was assembled without the hazard nops that `tools/masps2.py` inserts.** In FM asm, `mfc1` is never
  followed by a nop, `c.lt.s`/`c.le.s` are followed directly by `bc1t/bc1f`, `mtc1`/`li.s` are followed
  directly by an FPU op or `swc1`. masps2.py always adds nops there (JP needed them), so **any FM function
  with mfc1, c.lt.s, c.le.s, or mtc1/li.s followed by a float op cannot match with the current tools**.
  That's why many JP-matched float helpers are `#ifdef VERSION_FM INCLUDE_ASM` (e.g. xball func_00121970).
  Skipped for this reason: pppRandUpIV func_00189D70, pppSRandHCV func_0018B7F8, pppRandDownCV
  func_0018A4A8, pppSRandDownFV func_0018AFB8, pppDrawMdlLoop func_0018C818, xtailor fm_func_00110068,
  xapple func_0013BAC0, pppRyjDrawMatrixWorldDttFr func_001A3FE0, xball func_00120F78/func_00121970.
* `diff <func>` compares by address in the current build, so if any earlier function in link order differs
  in size, everything after it shows as different. When testing many functions in one build, compare each
  function against the original by its own start address (I used a small script that reads the built rom at
  the symbol address from `nm` and the target rom at the address in the .s file, masking %hi/%lo/jal fields).
* Fast iteration without a full build: run the game compiler on a temp copy of the C file in the WSL mirror
  (`~/kh1-build-<agent>`), the 32-bit cc1 can't read /mnt/* files, so copy the file into the WSL home first.
* Store order: gcc's scheduler tends to move the *last* store of a run up to the front. For
  target order `A B C` write `B C A`... in practice: write stores in natural/ascending order first and
  look at the result.
* C-defined bss arrays in a file (e.g. `ppvmng D_00360600[0x100]` in pppMngr.c) are NOT placed at the FM
  address. For FM code use the FM symbol from the asm as `extern` (e.g. `extern PppMngU D_00364130[];`).
* Pointer-typed stores alias pointer-typed globals: storing `NULL` through `void**` kept the `ppvMng` load
  after the stores (pppRyjMegaPlaceCon), while `u32`/struct-field stores let gcc hoist it.
* Unsolved pattern: `lui; addiu; sw $x, 0($reg)` for a single store to a global (xtailor func_00110230,
  func_0010FCF0, func_00110240). `volatile` gives the addiu form but then the store can't go in a delay slot.
  Plain/array/struct/float/initialized/static variants all fold to `sw %lo(sym)`. Still unknown.

## Second run (22 Nov)

### Big one: ppp code acts as if built with -fno-strict-aliasing

Many ppp targets keep a load after a store of a different type (float store then `pobj->time` reload; s32
store then pointer reload; float stack stores then s16 vertex loads). The build has strict aliasing on, so
make the accesses alias by hand:
* **union trick**: `typedef union { f32 f; s32 i; } FI;` and access the val area as `FI* v` / `v[0].f`
  (pppKeLnsLpSftCalc, pppDrawMdlTs3Calc; with a `void* p` member too for func_0018C818). For a stack vector
  passed to sceVu0ApplyMatrix: `union { sceVu0FVECTOR f; s16 s[8]; } v;` (pppVertexAttendCalc).
* **int typing**: write pointer fields as `s32` (`*(s32*)&v->lp = (s32)ptr`, a local struct with s32
  next/prev/owner for pppEMCB in pppFree).
Probably also true for xpotato (func_00218870 needed `s32 p[3]` to get a reload).

### Tools

My scratch scripts are in the scratchpad `a3/` folder: `cmp.py` (compile one src file in the WSL mirror
with the FM flags, compare named functions against the target .s by word, masking relocations),
`vary.py` (put `//VAR` in the C file where the function goes, write variants separated by `====` lines,
get a diff count for each in seconds), `show.py` (full side-by-side for one variant), `apply.py` (put a
variant in, wrapped in `#ifdef VERSION_FM ... #else INCLUDE_ASM #endif` or not), `bc.sh` (build and commit
only if the last line is `OK`; I once committed after a failing build because `| tail -1` hid the status).

### Other patterns

* **Jump tables**: FM has no `.rodata` split for most C files (config/kh.fm.yaml has `[0x390340, rodata]`
  for xpotato's area), so a `switch` that becomes a jump table fails to link (undefined `.L` labels from
  the rodata asm). Skip jump-table functions (`jtbl_` in the asm) until the yaml gets a split.
  (xpotato func_00218A38 / func_00218AC0: C is a trivial switch over XWhiskey fields 0,4,8,0x10,0x14,0x18,0x2C
  with `case 6: default:` sharing, matches byte-for-byte but can't link.)
* **`lui $1 / addu $1,$1,$reg / lw %lo($1)`** (gas macro with $at): gcc emits it for `array[i]` loads when
  the address isn't split; `p[i]` with a counter loop (instead of `*p++`) gave it in func_00215AF0.
* **Switch decision trees**: `slti x, 5` after `beq x,4` = cases 4 and 5 plus explicit lower cases sharing
  default (`case 0..3: default:`), on a *signed* switch value (`switch ((s32)u32var)`).
* **Compare order**: `if (a == b)` loads `a` second; swap operands when the two loads come out swapped.
* `lui/addiu/sw 0(reg)` for a single global store (xtailor func_00110230): an empty asm barrier
  `s32* p = &D; __asm__("" : "+r"(p)); *p = x;` reproduces it exactly; not committed (hack). volatile gives
  the addiu form but gcc won't put a volatile access in a delay slot, the target has it in one.

## Third run (22 Nov)

### Patterns learned

* **Union-typed global = reload after every store**: when the target re-loads a pointer global after each
  field store (`sw p,0($4)` then `sw/swc1 x,N($2)` then `lw $2,0($4)` ...), declare the global as
  `typedef union { T* p; f32 f; } U; extern U G;` and use `G.p->field` (xowl func_00123108, xapple
  func_0013B480). When the global is already declared with its real type in the file, cast at the use:
  `#define APL (((U*)&D_005325E8)->p)` (xapple func_0013B578). Not `volatile` (that also reloads before
  the first store).
* **`a = b = 0.0f` chain** gives `mtc1 $0,$f0` + two `swc1 $f0`; separate `a = 0.0f; b = 0.0f;` give
  `sw $0`. Use the chain when the target stores float zero from an FPU register (xball func_00121200,
  func_00120B40).
* **Store order of 4 constant stores** (D_002C6450[0..3] = 1.0f): no rule worked; I generated all 24
  permutations with vary.sh and took the matching one (written 3,2,1,0 gave target 0,3,2,1).
* **Range check `2 <= x < 5` as two `slti`** (not `addiu -2; sltiu 3`) came from `switch (x) { case 2:
  case 3: case 4: ... }` (xowl func_00122DD8).
* **`x & (1 << i)` kept as `sllv + and`** (instead of `srav; andi 1`) when x is `u32`.
* **Callee that returns a value**: declaring `void f()` vs `s32 f()` changes register choice right after
  the call (xapple func_0013B578: needed `s32 func_0014F658()`).
* **Index vs pointer for an output row**: `m[k++]` (k counter) gave the target's register order where
  `*p++` didn't (xowl func_00122DD8). `v[3 - (i + j)]` vs `v[3 - i - j]` fixed a register swap
  (xball func_00120B40).
* **gcc 2.96 float literals are parsed imprecisely**: `0.5235987f` came out 0x3F060A90; to get 0x3F060A91
  I had to write `0.5235987306f` (more digits). Check the hex of float constants in the diff.
* **Loop init order in a `for`**: `for (y = 148, i = 0; ...)` vs `for (i = 0, y = 148; ...)` swaps the two
  registers (xpotato func_002192D8).
* **Missing prototype = implicit int**: pppGetRotMatrixXYZ isn't declared by ppp.h; without a `void`
  prototype the call returns int and the next temp goes to $3 instead of $2 (pppRyjMatrixWorldXYZCon).
* **`pobj = NULL` placement**: initialising inside the `if` (not at the declaration) puts the `li 0` where the
  target has it (pppVertexApAt func_00186640).
* **Store order of a struct init (9 stores)**: target order = last statement first, then the others in source
  order, with the delay slot taking the final one (xbeginning func_00100B30). For three 4-element arrays I
  permuted each array's 4 stores separately with vary.sh, then combined the best (xtailor func_00110190).
* **`(s32)f` casts now compile to cvt.w.s (coordinator's news): the tiny ppp helpers
  `return a * b;` / `return a * b - a;` with s8/s16 params and returns all matched.

## Fifth run (22 Nov)

### Patterns learned

* **Callee defined earlier in the same file changes the caller's code.** func_001823B8 was 1 diff (`beql` vs
  `beqz` around a call) while its callee func_001821A8 was still INCLUDE_ASM; after matching func_001821A8 in C
  (it sits above), the very same caller C matched. So match small callees first, then retry their callers.
* **Bit-per-entry dpd loops** (`if (!(i & 7)) bits = use[i >> 3]; if (bits & 1) ...; bits >>= 1;`): when the
  target computes `i >> 3`, `i & 7` and `i++` before the branch and does the `use + k` add in the delay slot,
  write `j = i & 7; x = *p++; k = i >> 3; i++; if (j == 0) bits = use[k];` (for loop without increment).
  When the target increments i at the end, keep `for (...; i++)` but still split `j`/`k` out. With
  -fno-strict-aliasing the table store needs a local pointer (`pppShapeSt* d = &D_00363930[s[0]];`) or s[0]
  gets reloaded. Matched dpd_set_shape_data / rsd / vsf, func_00182288, func_001823B8, func_00181C20/D30.
* **Shared `return r` label**: when two paths both end in `daddu $2,$16` (one of them as a branch delay slot),
  the source had one `return r;` at the end and an if/else, not two returns (op1_md_draw).
* **`register T x asm("$16")`** fixes pure register-allocation swaps between callee-saved registers
  (xapple func_0013AFE8: `register s32* q asm("$16") = &D_0052AE60;`; xtailor func_00110C70: `i` in $18 and
  the `&D_002B9090[i]` pointer in $17). It's GCC-legal C and only steers allocation; I used it only after
  ordinary variants failed. Forcing a register that is set from `lui` makes the `lui` go straight into it
  (prologue changes), so force the other variables instead when that happens.
* **Unused array local for the frame size**: target frame 0x20 with ra at 0x10 but no stack use = 16 bytes of
  locals that got optimised away; an unused `sceVu0FVECTOR v;` reproduces it (xtailor func_00110AE0).
* **Adjacent u8 flags tested together**: `ppvMng->stop || ppvMng->unk_B4 != 0` compiles to `ld 0xB0 & mask`
  (fold_truthop), no u64 cast needed.
* **Case order = block order in a jump-table switch**: the case bodies are laid out in source order; reorder the
  cases to match the label order in the jtbl targets (func_00181640).
* **`e += a * b; e += 0x10;`** (two statements) kept the in-place `addu $8,$4,$8; addiu $8,$8,0x10`.
* **gcc float literal parsing again**: PI written as 3.1415927f came out 0x40490FDA; 3.1415928f gives
  0x40490FDB.
* cmp.py now skips the jtbl `.word` lines before `glabel` (they used to shift the whole comparison).

### Rules for the 991111 library compiler / FM's SDK
* **DIntr/EIntr (and any call whose result is unused) must be declared with the return type the callee really
  has.** `int DIntr(void)` vs `void DIntr(void)`: with void, the temp after the call is put in $2; with int it
  moves to $3 and everything after is renumbered (sifrpc InitRpc/SetRpcQueue/RemoveRpcQueue/ExecRequest). The
  reverse in tlbfunc: the syscall stub whose result nobody reads (func_00260928) must be `void`.
* **991111 only tail-calls (`j f` after tearing down the frame) when the call's value is not returned.** A
  wrapper whose callee value is returned gets `jal` + return; `void` wrappers get `j`. func_00260AC0 needed
  `return InitTLB32MB();`. newlib's strtol (func_00272C38) tail-calls a value-returning function = 2.96 code.
* **991111 emits the two-instruction truncation `dsll32/dsra32` as ONE insn**, so it never goes into a delay
  slot (ftoi's `jr; dsra32` in the ROM cannot be made; see below).
* **The assembler never fills `j $31` delay slots itself** (gas here does no reordering); what the compiler
  does not fill stays a nop. The 3-4 nops in short loops (`andi; nop; nop; nop; bnez`) come from gas and need
  nothing in C.
* **Syscall stubs** (`addiu $3,$0,N; syscall 0; jr $31; nop`) match as `T name() { __asm__ volatile("addiu
  $3, $0, N\n\tsyscall 0"); }` (K&R definition so callers can pass arguments; T = int or void as above).
* **Bitfield request word in a register** (libpad2 GetState/GetButtonProfile: 64-bit masks on an uninitialised
  saved register, then dsll32/dsra32 to pass it as int): `union { struct { unsigned long a:14, b:2, c:8, d:8; }
  f; int i; } cmd; cmd.f.a = ...; f(cmd.i)`. With `unsigned int` fields the masks are 32-bit; with an 8-byte
  struct aligned 4 it goes to the stack (BLKmode).
* **Shared RPC buffer accessed through a struct-pointer local** (libdbc): `Buf *p = (Buf *)D_00669B80;` for
  the fields, the array name itself for the CallRpc arguments; gives the ROM's base register and the hoisted
  `p + 0xC` copy pointer.
* String literals and other rodata used by a function: `extern char D_xxxxxxxx[];` and pass that (thread's
  kprintf message, libdbc's DPRINT messages, libpad2's "") builds exact. Double constants loaded from the
  constant pool (`lui $1; ld $5, %lo(...)($1)`) can NOT be faked with an extern double (the address gets split
  into saved registers): those functions need their rodata moved to C.
