## Learned (third run)

- **VU0 helpers work** (a2's approach): `vu0Rand()` as `static inline` asm with `"=r"(r)` matched func_0018AA40,
  func_0018B1F8 (`r = (r + rand) * 0.5f`), func_0018BA38 (`r = rand; r = -r;` — `r = -vu0Rand()` allocates
  differently), func_001A5500 (`return vu0Rand();`). A whole hand-written function (func_0010A1F8, a VU0 loop) is
  a `.set noreorder` asm block with explicit `$4..$11` and a `1:`/`1b` label; the compiler adds the final
  `jr $31; nop` itself. Mixed C + VU0 (func_0019B458): C for the scalar part, then asm with `"r"` inputs; gcc kept
  the right registers.
- **Delay slots**: gcc never moves an asm statement into a delay slot (no `vrinit` in `jr`'s slot) and never a
  volatile store either.
- **Sandbox vs build**: the objdump sandbox (scratchpad/a5/cc2.sh = ppp flags, cc3.sh = `$CFL` flags, t.sh/t3.sh
  wrappers) matches the build closely, but branch-likely choice can differ (func_001F0960: sandbox bnezl, build
  bnez). Check promising candidates in the build.
- **Loops not rotated** (test at top, `slti` re-done in a `continue` path's delay slot): the source used `goto`
  loops (func_001F0960). for/while loops always get rotated/peeled.
- **Copy chain of base registers** (`t0 = s3; t1 = t0; ...` then `sw a0,0(t0); sw a1,4(t1)...`): repeated
  `G[n][k] = argk;` on a global 2D array (func_001EE0B8). `p[k]` gives one register, `*p++` an addiu chain.
- **Init order**: initialised locals come out in the order they get registers; permute declarations
  (func_0019B5C0: `th, tx, tw`).
- **Loop variable reuse decides s-register**: func_00114A50's second loop reused `j` (inner loop of the first)
  so `j` lives in `$s0` and `i` in `$a0`.
- **Separate base pointer for a branch**: func_00246C80: when both branches load the same field into the same
  register, reorg hoists it into a plain branch slot; target had `beqzl` + different registers: use a different
  local (`MonitorKey* e`) in the else branch and a different address expression (`(T*)(i * 32 + base)`) in the
  then branch. A loop with `s32* o = &out[i]; *o = ...` keeps an up-counting index with pointer increments.
- `return X;` inside the if *and* after it fixes `lw` scheduled after `ld ra` (func_001EDD20, as in func_001EE330).
- `size != sceRead(...)` vs `sceRead(...) != size` swaps `xor` operands.
- 64-bit `ld` of a 32-bit flags field: `(*(u64*)&m->unk60 & 0xA) == 0xA` (xmonitor).
- Division by a constant with a zero check (`beql $c,$0; break 7`): gcc emits that check for u32/s32 constant
  divisors here too, nothing special needed (func_001EF330: plain `t / 216000; t %= 216000; ...`).
  func_001EDD20 used `s32 base = 48000;` and it matched as well.
- f32 constant 0x3FD55555: write `(100.0f / 60.0f)`; `1.6666666f` rounds to ...54.
- **Loop exit test in `$v1` instead of `$v0`** after a call in the loop: the callee returns a value (declare it
  `s32`, not `void`), so `$v0` is taken (func_001144C8).
- String literals in a function's own .rodata piece (func_001128F0 `".img"`) just work as C literals.
- `lq/sq` copy of a vector: `*(u_long128*)dst = *(u_long128*)src;`.

## Learned (second run)

- **`cvt.w.s` (`.word 0x46000064` etc.) is fine**: our compiler emits `cvt.w.s` for plain `(int)` casts of
  floats here, and all six ppp int<->float helpers matched as plain C once masps2 stopped adding nops
  (`s8 f(s8 a, f32 b) { return a * b; }`, `s32 f(s32 a, f32 b) { return a * b - a; }`,
  `s8 f(u8 a) { f32 r = g(); return (a * 2) * r - (a >> 1); }`). The MATCHING.md note about skipping them
  looks outdated. u32<->f32 (`bltz`/`or` + `0x4F000000` compare) also comes straight from C (func_001EF210).
- **Union types change alias sets** (strict aliasing is on): accessing fields through a union makes stores
  conflict with each other / with other loads, which
  * forces a reload after a store (pppKeGrvTgtCalc: float fields as `union { f32 f; void* p; }` made
    `ctbl->useVal` be re-read after the float stores),
  * stops the scheduler moving one base's stores past another's (pppKeThCon/Con2: wrapping the object and its
    sub-struct in `union { T v; u8 raw[N]; }`; inside one base the order is still "last first", so permute),
  * changes load scheduling (func_00194BD0: source fields as `union { f32 f; s32 i; }`).
  When store/load order is right but can't be reached by permuting, try unions before giving up.
- **`volatile` as a scheduling fix**: in func_00113660 two global structs declared `volatile` gave exactly the
  source order (and the lui/addiu/0(reg) form). But volatile stores are never put in a delay slot, so it fails
  when the target's last store sits in `jr`'s delay slot (pppKeThCon2): use the union trick there.
- **lb vs lbu for s8 globals**: `s32 i = spr_index; spr_index = i - 1;` gives `lb`; `spr_index--` gives `lbu`.
- **Argument passed through**: if `$a1` is never touched and the callee gets an extra arg, the function
  probably forwards its own parameter (pppRyjMegaPlaceShapeCalc: `func_0019FD78(data, p)`). Same for
  func_001EFC40 (`func_001495C8(arg0, arg1)` with no `$a1` set).
- **Separate base registers per field** in a loop over a struct array (`base`, `base+4`, `base+8` each in an
  s-register, index `i*12`): index a real global array of structs (`D.slot[i].f`), not a cast pointer
  (`((T*)D)[i]` gave one pointer). For xnoodle D_002B3AF0 I made the definition a union
  `{ s32 raw[8]; XNoodleSlot slot[2]; }` (same bytes).
- **Address sum kept in a temp, then `s0 = arg1 + tmp`** (xtango stat queries func_001EFF90 etc.): use a local
  `XTangoChar* chr = &party->chars[arg0];` and index it directly (`chr->unk_19[arg1]`) for the load and both
  stores; a `u8* p = &chr->unk_19[arg1]` pointer gives a different allocation.
- **Index from a loaded byte**: `s32 idx = ...->unk_48E[i]; XTangoChar* chr; ...; chr = &chars[idx];
  chr->unk_32` matched where `chars[idx].unk_32` directly got the offset split (`base+6` hoisted, `0x30`).
- `s32 c = arr[i]; if (c == 0) break; if ((c & ~0x80) == x) count++;` gives the target's `and` with `-0x81`
  and bottom-tested loop.
- Unused `char buf[0x400];` locals still take stack space (op_file_size's 0x420 frame).
- Bitfields: xmonitor func_002475E8 is `sceGsTex0` (eestruct.h) `CSA = 0; CLD = 1; PSM = 0x13;`; three
  consecutive bitfield stores fold into one ld/and/or/sd.
- Fast sandbox: `scratchpad/a5/cc.sh` compiles a file in `~/kh1-build-a5` with the FM flags and
  `MASPS2_NO_NOPS=1`; the `gen*.py` scripts there put all statement permutations into one file and grep for
  the target sequence (a 5040-function file compiles in well under a minute). Don't name test functions
  `f%d` (`f32` clashes with the typedef). The sandbox output doesn't show delay-slot filling exactly; the
  build does.

## Learned (first run)

- Store order of independent stores: gcc here tends to emit the *last* C store first (or second); e.g.
  C `a0=0; a4=0; a8=0;` comes out `a8, a0, a4`. Write fields in natural order first and permute from there.
- `x = y = z = 0.0f` chained gives `mtc1 $0,$f0` + `swc1` (store order x, z, y); separate `= 0.0f` gives `sw $0`.
- No tail call (`jal` + `ld ra` + `jr`) where you'd expect `j`: make the function return a value (s32) while the
  callee is void.
- `addiu reg, base, off` + `lw 0(reg)` hoisted before a branch: take the field's address into a local before the `if`.
- `lui/addiu` + `0(reg)` for a global: it's either volatile, or the address is used twice (load + store).
- FM-only callees named `fm_func_*` inside an unmarked function: wrap the C in `#ifdef VERSION_FM` with the
  `INCLUDE_ASM` in `#else` so JP keeps its asm.
- xmonitor: object with flags at 0x60 and three 0x14-byte sub-objects at 0x64/0x78/0x8C (flags at +0x10).
- xnoodle D_002B3AF0: two 0xC-byte IO slots `{ void (*fn)(IOReadTask*); IOReadTask* task; s32 unk_8; }`;
  func_0010BE60 is the IO thread (WaitSema, run each slot's callback, set unk_8 = 1).

Learned:
- **The sandbox must not use `-g`** (the build has none): `-g` changed func_00114B50's code. My cc4/cc5.sh
  now compile without it; cc5.sh even compiles the copy as `src/<same-length name>.c` inside the WSL mirror.
- **Code of a later function can depend on how many function declarations come before it** (cse hashes
  symbol addresses): in xblade, one extra prototype anywhere before func_00114B50 turns its
  `la $4, D_004D9420($4)` (assembler `$1` form) into lui/addiu/addu, or its `D_003044D8[idx].unk_00` load
  into lui/addiu/addu/lw. Extern *variables* don't matter. Fix: drop a prototype (call it implicitly
  declared) and re-check with a build-identical compile (chkb.sh in my scratch folder). If a build fails with
  a romdiff range in a function you didn't touch, suspect this.
- **Header says `void` but the function returns a value**: declare it under another C name with an asm
  label, `s32 func_X_s32(void) __asm__("func_X");`, then define `func_X_s32` (func_00113CB8,
  func_0010BF98, func_00114480 = "return s32, no return statement" to avoid the tail call). A plain
  definition conflicts with the header.
- **Callee returns a value**: `void f();` vs an int-returning declaration changed scheduling (`li $16,1`
  before/after a `lui`) in func_00113170; FM-only callee names (func_00105860 = JP func_00105660) come from
  the asm, jp_names.txt has no entry for them.
- **Dead `li` left in the output** (func_00247668 `li $4,0x50` next to the divide check): an unused
  division `i = f->unkC / sizeof(MonitorKey50);` leaves its constant load.
- **Loop not strength-reduced** (index * 0x50 recomputed, `n - 1` recomputed each pass): the loop reads
  `s->unk4`/`s->unk8` through the struct each time (func_00246D68: `while (s->unk0 >= keys[s->unk4].time)`
  with the end test inside); copying them to locals lets loop.c optimise it.
- **Address sum order**: `(T*)(i * 80 + base)` vs `&((T*)base)[i]` swaps `addu` operands.
- **Two adjacent locals get the regs in declaration order**: pppRyjMatrixNoRotCalc needed `pos` declared
  before `scl`.
- **Inline-block locals fix a register**: func_0018FBB0's first child creation needed `pdv` in a `{ }`
  block of its own (target put it in `$5` directly).
- **`if (x == one)` with `s32 one;` set after the early-out**: keeps `bne $2,$4` (a compare against a
  register holding 1) instead of folding `(x & 1) == 1` to `beqz`. Also `D_A = D_B;` inside
  `if (D_B == one)` gives `sw $2` of the loaded value.
- Whole hand-written function with a stack frame (func_0019B2A0: 0x240 frame, s0-s3 saved with `sq`):
  a `sceVu0FVECTOR tmp[32];` local plus clobbers `$8..$19` make gcc emit exactly that prologue/epilogue; the
  body is one `.set noreorder` asm block with numeric labels (hwgen.py in my scratch folder converts the
  .s; the last label goes just before `.set reorder`).
- objdump hides runs of zero words as `...`: use `objdump -z` when comparing nops.
