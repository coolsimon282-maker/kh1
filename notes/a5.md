## Learned

- Store order of independent stores: gcc here tends to emit the *last* C store first (or second); e.g.
  C `a0=0; a4=0; a8=0;` comes out `a8, a0, a4`. Write fields in natural order first and permute from there.
- `x = y = z = 0.0f` chained gives `mtc1 $0,$f0` + `swc1` (store order x, z, y); separate `= 0.0f` gives `sw $0`.
- No tail call (`jal` + `ld ra` + `jr`) where you'd expect `j`: make the function return a value (s32) while the
  callee is void.
- `addiu reg, base, off` + `lw 0(reg)` hoisted before a branch: take the field's address into a local before the `if`.
- `lui/addiu` + `0(reg)` for a global: it's either volatile, or the address is used twice (load + store).
- FM-only callees named `fm_func_*` inside an unmarked function: wrap the C in `#ifdef VERSION_FM` with the
  `INCLUDE_ASM` in `#else` so JP keeps its asm.
- xmonitor: object with flags at 0x60 and three 0x14-byte sub-objects at 0x64/0x78/0x8C (flags at +0x10).
- xnoodle D_002B3AF0: two 0xC-byte IO slots `{ void (*fn)(IOReadTask*); IOReadTask* task; s32 unk_8; }`.
- `pppKeGrvTgtCalc` (pppKeGrvTgt): `if (p->cdt.time == pobj->time) { v = &val[useVal[1]]; v->x = p->x; v->y = p->y;
  v->target = &val[useVal[0]]; }`. Target re-reads `ctbl->useVal` after the two float stores (as if they could
  alias); our build hoists it (strict aliasing). A 2-float struct copy gives ldl/sdl instead.
- `func_001EFF90` (xtango): same as func_001EFF28 but on `chars[arg0].unk_19[arg1]` and returns `buf[15]`; only
  the register allocation of the D_003010F8 + index sum differs (target keeps it in a temp, then `s0 = arg1 + tmp`).
  Tried `&chr->unk_19[arg1]`, `arg1 + ...unk_19`, and direct indexing.
