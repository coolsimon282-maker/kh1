## Learned (third run)

- **VU0 helpers work** (a2's approach): `vu0Rand()` as `static inline` asm with `"=r"(r)` matched func_0018AA40,

- **Sandbox vs build**: the objdump sandbox (scratchpad/a5/cc2.sh = ppp flags, cc3.sh = `$CFL` flags, t.sh/t3.sh

- **Copy chain of base registers** (`t0 = s3; t1 = t0; ...` then `sw a0,0(t0); sw a1,4(t1)...`): repeated

- **Init order**: initialised locals come out in the order they get registers; permute declarations

- **Loop variable reuse decides s-register**: func_00114A50's second loop reused `j` (inner loop of the first)

## Learned (second run)

- **`cvt.w.s` (`.word 0x46000064` etc.) is fine**: our compiler emits `cvt.w.s` for plain `(int)` casts of
  floats here, and all six ppp int<->float helpers matched as plain C once masps2 stopped adding nops
  (`s8 f(s8 a, f32 b) { return a * b; }`, `s32 f(s32 a, f32 b) { return a * b - a; }`,

  looks outdated. u32<->f32 (`bltz`/`or` + `0x4F000000` compare) also comes straight from C (func_001EF210).
- **Union types change alias sets** (strict aliasing is on): accessing fields through a union makes stores
  conflict with each other / with other loads, which
  * forces a reload after a store (pppKeGrvTgtCalc: float fields as `union { f32 f; void* p; }` made
    `ctbl->useVal` be re-read after the float stores),
  * stops the scheduler moving one base's stores past another's (pppKeThCon/Con2: wrapping the object and its
    sub-struct in `union { T v; u8 raw[N]; }`; inside one base the order is still "last first", so permute),
  * changes load scheduling (func_00194BD0: source fields as `union { f32 f; s32 i; }`).
  When store/load order is right but can't be reached by permuting, try unions before giving up.
- **`volatile` as a scheduling fix**: in func_00113660 two global structs declared `volatile` gave exactly the
  source order (and the lui/addiu/0(reg) form). But volatile stores are never put in a delay slot, so it fails

## Learned (first run)

- Store order of independent stores: gcc here tends to emit the *last* C store first (or second); e.g.
  C `a0=0; a4=0; a8=0;` comes out `a8, a0, a4`. Write fields in natural order first and permute from there.

- `lui/addiu` + `0(reg)` for a global: it's either volatile, or the address is used twice (load + store).
- FM-only callees named `fm_func_*` inside an unmarked function: wrap the C in `#ifdef VERSION_FM` with the
  `INCLUDE_ASM` in `#else` so JP keeps its asm.

- R-N1. Renaming an identifier inside src/unsplit/ or xhumungus.c moves other functions (rule F1): renaming 5

  config/fm/undefined_syms.txt links old and new (`old = new;`, or `new = old;` where the fragile file defines it).
- R-N2. A header those files include must keep the old declaration too: renaming it made the old name undeclared in

  keeps the old prototype and adds `#define NewName old_name` (common_funcs.h, xarcade.h, xcursed.h), so every

  symbol_addrs.txt / jp_names.txt (moving a line from jp_names.txt to symbol_addrs.txt is the rename).
